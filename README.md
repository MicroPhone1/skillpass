# SkillPass — ฝึกจนเป็น พิสูจน์ได้

ต้นแบบ (prototype) แพลตฟอร์มเตรียมความพร้อมและฝึกทักษะ พัฒนาต่อยอดจากแนวคิด
*Certification Readiness Platform* โดยขยายขอบเขตออกไปสองทาง:

1. **เพิ่มการตรวจภาคปฏิบัติด้วยกล้อง** — ข้อสอบวัดได้ว่าคุณ "รู้" แต่ใบรับรองสายปฏิบัติวัดว่าคุณ "ทำเป็น"
2. **ไม่จำกัดแค่สายอาชีพ** — เอนจินเดียวกันใช้ได้กับ IT, ภาษา, ปฐมพยาบาล, ห้องแล็บ, การนำเสนอ และการเงินส่วนบุคคล
3. **ปิดวงจรด้วยเกียรติบัตร** — มีบัญชีผู้ใช้ โปรไฟล์ และเกียรติบัตรที่ออกให้ต่อเมื่อมีหลักฐานว่าผ่านทั้งสองภาคจริง

โทนฟ้า–ขาว · ใช้ได้ทั้งบนคอมพิวเตอร์และมือถือ · ไม่ต้อง build ไม่ต้อง `npm install`

## เริ่มใช้งาน

```bash
cd ~/Desktop/projects/skillpass
python serve.py
```

จากนั้นเปิดลิงก์ที่แสดงในหน้าต่างคำสั่ง:

```
บนเครื่องนี้   https://localhost:8443
บนมือถือ      https://192.168.x.x:8443     (ต่อ Wi-Fi วงเดียวกัน)
```

> **ทำไมต้องใช้ `serve.py` แทนการเปิด `index.html` ตรง ๆ**
> - แอปใช้ ES modules ซึ่งเบราว์เซอร์บล็อกเมื่อเปิดผ่าน `file://`
> - `getUserMedia` (กล้อง/ไมค์) ทำงานเฉพาะบน **HTTPS หรือ localhost** เท่านั้น
>   ถ้าจะทดสอบกล้องบนมือถือผ่าน Wi-Fi ต้องเป็น https
>
> สคริปต์จะสร้างใบรับรอง self-signed ให้อัตโนมัติ (ใช้ `openssl` ที่มากับ Git for Windows)
> ครั้งแรกเบราว์เซอร์จะเตือน — กด **Advanced → Proceed** (Chrome/Edge)
> หรือ **Show Details → visit this website** (Safari/iOS)

ถ้าไม่มี `openssl` สคริปต์จะถอยไปใช้ HTTP ให้อัตโนมัติ (กล้องจะใช้ได้เฉพาะบนเครื่องนี้)

**ครั้งแรกที่เปิด** จะเจอหน้าเข้าสู่ระบบ — กด **“ลองใช้แบบผู้เยี่ยมชม”** เพื่อเข้าใช้ทันที
หรือสมัครบัญชีจริงถ้าต้องการให้ชื่อขึ้นบนเกียรติบัตรและแยกความคืบหน้าออกจากคนอื่นที่ใช้เครื่องเดียวกัน

```bash
python serve.py --http          # บังคับ HTTP
python serve.py --port 9000     # เปลี่ยนพอร์ต
```

## ระบบภายใน 6 ส่วน

### 1 · Adaptive Test Engine — `js/engine/adaptive.js`

ทำงานจริงด้วยโมเดล **IRT แบบ Rasch** ในเบราว์เซอร์

```
P(ตอบถูก) = 1 / (1 + e^(−1.7·(θ − b)))
```

- **เลือกข้อถัดไป** จาก Fisher information สูงสุด ณ ระดับ θ ปัจจุบัน
  (ตอบถูก → ได้ข้อยากขึ้น · ตอบผิด → ได้ข้อง่ายลง) พร้อมโบนัสให้ทักษะที่ยังวัดน้อย
  เพื่อไม่ให้ข้อสอบกระจุกอยู่เรื่องเดียวจนพลาดจุดอ่อนที่ซ่อนอยู่
- **ประมาณค่า θ แบบ MAP** ด้วย Newton–Raphson วนจนลู่เข้า บนรูปแบบคำตอบทั้งหมด
  ใช้ prior แบบปกติถ่วงไว้ เพราะ MLE ล้วนจะลู่ออกอนันต์เมื่อตอบถูกทุกข้อ
- **รองรับ 4 ชนิดข้อสอบ**: ปรนัย · เลือกหลายข้อ (ให้คะแนนบางส่วน) · คำนวณ (มี tolerance) · เรียงลำดับ
- **สอบจำลอง** สลับไปกระจายความยากแบบข้อสอบจริงพร้อมจับเวลา

พฤติกรรมที่วัดได้จริง (จาก `tests/smoke.mjs`, ชุด 10 ข้อ):

| รูปแบบคำตอบ | θ | Readiness |
|---|---|---|
| ถูกทุกข้อ | 2.19 | 94% |
| ถูก 80% | 1.25 | 81% |
| ถูก 50% | 0.41 | 56% |
| ถูกเฉพาะข้อง่าย | −0.14 | 36% |
| ผิดทุกข้อ | −2.03 | 4% |

### 2 · Practice Lab — `js/engine/vision.js` ★ ส่วนที่เพิ่มจากแนวคิดเดิม

เปิดกล้อง/ไมโครโฟนจริง ประมวลผลในเบราว์เซอร์ด้วย Canvas 2D ล้วน — ไม่พึ่งไลบรารีภายนอก

วิธีทำงาน: ย่อภาพเป็น 160×120 (มิเรอร์ให้ตรงกับที่ผู้ใช้เห็น) → เกรย์สเกล →
หาผลต่างระหว่างเฟรม = พลังงานการเคลื่อนไหว → ต่อยอดเป็น 6 โหมด

| โหมด | วัดอะไร | ใช้กับ |
|---|---|---|
| `tempo` | หาจุดยอดของสัญญาณด้วย Schmitt trigger → ครั้ง/นาที + ความสม่ำเสมอ | CPR 100–120/นาที, ส่ายลวดเชื่อม |
| `steady` | คาลิเบรตฉากหลัง 2 วินาที แล้ววัดการสั่นในกรอบ | จับโพรบมิเตอร์, ปิเปตต์, บานแฟลร์ |
| `zone` | พลังงานการเคลื่อนไหวรายโซน + เวลาตอบสนอง | หยิบเครื่องมือให้ถูกชิ้น, ตรวจรอบรถ |
| `sequence` | เหมือน `zone` แต่ตรวจ **ลำดับ** และจับได้เมื่อข้ามขั้น | LOTO 5 ขั้น, ตรวจ PPE, ขันน็อตแบบดาว |
| `frame` | การกระจายพลังงาน → อยู่ในกรอบไหม / โยกตัวแค่ไหน | ยืนนำเสนอ |
| `voice` | Web Audio วัด envelope → พยางค์/วินาที + สัดส่วนการหยุด | คุมจังหวะการพูด |

ทุกบทฝึกให้คะแนนตาม **rubric ถ่วงน้ำหนัก** พร้อมคำแนะนำที่อ้างอิงค่าที่วัดได้จริง
(เช่น *"คุณทำเฉลี่ย 137 ครั้ง/นาที ซึ่งเร็วกว่าเป้าหมาย 120"*) และมีเมโทรนอมในตัว
สร้างเสียงด้วย Web Audio สำหรับโหมด `tempo`

**ความเป็นส่วนตัว:** ภาพประมวลผลบนเครื่องผู้ใช้เท่านั้น ไม่มีการอัปโหลดหรือบันทึกวิดีโอ
ระบบเก็บเฉพาะคะแนนลง `localStorage`

### 3 · RAG Tutor — `js/engine/tutor.js`

Retrieval **ทำงานจริง**, generation เป็นเทมเพลต — จึงไม่มีโอกาสแต่งเนื้อหาขึ้นเอง

- ภาษาไทยไม่มีช่องว่างระหว่างคำ จึงใช้ **character 3-gram** ผสมกับการตัดคำละติน
- ตัด **stopwords** ทั้งสองฝั่ง (`คืออะไร`, `ยังไง`, `ทำไม`, …) เพราะคำพวกนี้สร้าง n-gram
  จำนวนมากที่ไม่มีความหมายเชิงเนื้อหา ทำให้คำถามนอกเรื่องได้คะแนนสูงเกินจริง
- จัดอันดับด้วย TF-IDF แล้ว **กรองสองชั้น**: `score ≥ 0.25` **และ** `coverage ≥ 0.40`
  (coverage = สัดส่วนน้ำหนัก idf ของคำค้นที่พบจริงในเอกสาร)
- ถ้าไม่ผ่านเกณฑ์ → ตอบว่า **"ยังไม่พบข้อมูลเรื่องนี้"** แทนการเดา
- ทุกคำตอบแสดง **แหล่งอ้างอิง** ที่ตามรอยกลับไปยังเอกสารต้นทางได้

ค่าเกณฑ์ได้จากการคาลิเบรตกับคำถามตรงเรื่อง 20 ข้อและนอกเรื่อง 10 ข้อ
(รันซ้ำได้ด้วย `node tests/retrieval-calibration.mjs`)

### 4 · Skill-Gap Dashboard — `js/views/progress.js`

แผนภูมิใยแมงมุมวาดด้วย SVG เอง เทียบสามเส้น: **ระดับของคุณ · ค่าเฉลี่ยรุ่นเดียวกัน · เป้าหมายสอบผ่าน**
พร้อมคะแนนความพร้อม แนวโน้มย้อนหลัง และ **แผนติวเฉพาะจุด** ที่เรียงลำดับจากทักษะอ่อนสุด
แต่ละขั้นมีปุ่มพาไปทำต่อได้ทันที (ข้อสอบเจาะทักษะ → ติวเตอร์ → บทฝึกกล้อง)

### 5 · Gamification — `js/store.js`

ส่วนที่ตอบโจทย์ "อยากให้เด็กฝึกฝนและใฝ่รู้":

- **"รู้ไว้ใช่ว่า" ประจำวัน** — คำถามชวนคิดที่ไม่มีในข้อสอบ เช่น
  *"ทำไมนกเกาะสายไฟแรงสูงแล้วไม่ตาย"* เพื่อดันความอยากรู้ ไม่ใช่แค่การท่องเพื่อสอบ

### 6 · ห้องครู — `js/views/teacher.js`

สลับมุมมองได้จากแถบซ้าย · คัดกรองว่า **ใครต้องช่วยก่อน** และ **ควรสอนซ่อมเรื่องอะไร**
พร้อมแผนจัดคาบที่ระบบเสนอให้ ตอบโจทย์ปัญหา "ครูมีภาระมาก ให้ feedback รายคนไม่ไหว"

### 7 · บัญชีผู้ใช้ — `js/auth.js` + `js/views/auth.js`

รองรับผู้ใช้หลายคนบนเครื่องเดียว ข้อมูลของแต่ละบัญชีแยกคีย์กันใน localStorage
(`skillpass.v2:<uid>`) สลับบัญชีแล้วความคืบหน้าไม่ปนกัน

- **รหัสผ่านไม่ถูกเก็บเป็นข้อความเปล่า** — แฮชด้วย PBKDF2-SHA256 150,000 รอบ
  พร้อม salt เฉพาะบัญชี ผ่าน Web Crypto API (มีทางถอยเมื่อเปิดผ่าน http
  ที่ไม่ใช่ secure context โดยติดธง `weak` ไว้ให้เห็นชัด)
- เทียบแฮชแบบ **constant-time** และตอบข้อความเดียวกันทั้งกรณีไม่มีบัญชีและรหัสผิด
  เพื่อไม่ให้เดาได้ว่าอีเมลไหนมีอยู่จริง
- **โหมดผู้เยี่ยมชม** ใช้ได้ทุกฟีเจอร์โดยไม่ต้องสมัคร
- มีตัววัดความแข็งแรงของรหัสผ่านตอนสมัคร และเปลี่ยนรหัสผ่านได้จากหน้าโปรไฟล์

### 8 · โปรไฟล์ — `js/views/profile.js`

ข้อมูลส่วนตัว (ชื่อ อีเมล เบอร์ สถาบัน ตำแหน่ง เป้าหมาย แนะนำตัว) · รูปโปรไฟล์
ที่ย่อเหลือ 256 px ก่อนเก็บเพื่อไม่ให้ localStorage เต็ม · **ประวัติการศึกษาและ
การทำงาน** แบบเพิ่ม/ลบเองได้ · ประวัติการฝึกในระบบที่บันทึกอัตโนมัติ ·
และส่วนจัดการบัญชี (เปลี่ยนรหัสผ่าน ออกจากระบบ ล้างความคืบหน้า ลบบัญชี)

ช่อง **"ชื่อ–สกุลบนเกียรติบัตร"** แยกจากชื่อที่แสดงในระบบ แก้ที่นี่แล้วเกียรติบัตรทุกใบ
อัปเดตตามทันที

### 9 · AI Gateway — `aigateway.py` + `js/ai/`

ต่อโมเดลภาษาจริงเข้ากับระบบ โดยยึดหลักว่า **AI เป็นของเสริม ไม่ใช่ของที่ขาดไม่ได้** —
ถ้า gateway ล่ม ไม่มีคีย์ หรือโควตาหมด ทุกฟีเจอร์ยังทำงานได้ด้วยเอนจิน RAG ในเครื่องเหมือนเดิม

```
เบราว์เซอร์ ──POST /api/ai──► serve.py ──► aigateway.py ──► Ollama (ในเครื่อง)
                                                        └─► Gemini (ถ้าตั้งคีย์)
```

**ทำไมต้องมีตัวกลาง ไม่เรียก API ตรงจากเบราว์เซอร์**

1. API key ต้องไม่หลุดไปฝั่ง client — ใครเปิดหน้าเว็บก็อ่าน JS ได้
2. system prompt เก็บฝั่งเซิร์ฟเวอร์ client ส่งได้แค่ "ข้อมูล" ไม่ใช่ "คำสั่ง" จึงแก้บทบาทของโมเดลจากหน้าเว็บไม่ได้
   (มีเทสต์ยิง `system`/`template` ปลอมเข้ามาเพื่อยืนยัน)
3. เปลี่ยนผู้ให้บริการได้โดยไม่ต้องแตะโค้ดหน้าเว็บเลย

**แบ่งหน้าที่ตามงาน** — ไม่ใช้ prompt ก้อนเดียวทำทุกอย่าง แต่ละบทบาทมี system prompt,
อุณหภูมิ และ JSON schema ของตัวเอง

| บทบาท | หน้าที่ | temp |
|---|---|---|
| `tutor` | ตอบคำถามจากเอกสารที่ค้นเจอเท่านั้น มี `grounded` บอกว่าเจอจริงไหม | 0.25 |
| `explainer` | ชี้ว่าเข้าใจผิดตรงไหน แล้วพาคิดใหม่ทีละขั้น | 0.20 |
| `assessor` | ตีความ θ/se/สถิติรายทักษะเป็น "อ่อนตรงไหน เพราะอะไร" | 0.15 |
| `coach` | ออกแบบแผนพัฒนา: ทำอะไร กี่นาที วัดสำเร็จยังไง | 0.35 |
| `practice` | แปลงตัวเลขจากกล้องเป็นคำแนะนำที่แก้ได้ทันที | 0.30 |

งานที่ต้องแม่นใช้อุณหภูมิต่ำกว่างานที่ต้องคิดกว้าง — มีเทสต์บังคับความสัมพันธ์นี้ไว้

**การตั้งค่า** — สร้างไฟล์ `.env` ข้าง `serve.py` (ถูก gitignore ไว้แล้ว)

```bash
# แบบรันในเครื่อง — ฟรีถาวร ไม่ต้องมีคีย์ ข้อมูลนักเรียนไม่ออกนอกเครื่อง
SKILLPASS_AI_PROVIDER=ollama
SKILLPASS_AI_MODEL=qwen3:8b
```
```bash
winget install Ollama.Ollama
ollama pull qwen3:8b          # ~5.2 GB · ต้องมี VRAM ราว 6 GB
```

หรือใช้ Gemini (ต้องเป็นคีย์จากโปรเจกต์ที่ **ไม่ได้ผูก billing** ไม่งั้นจะไม่ได้โควตาฟรี):

```bash
SKILLPASS_AI_PROVIDER=gemini
GEMINI_API_KEY=xxxxx          # ขอที่ https://aistudio.google.com/apikey
```

**ความเร็วที่วัดได้จริง** (qwen3:8b บน RTX 5060 8GB):

| | เวลา |
|---|---|
| คำขอแรกหลังเปิดเครื่อง | ~53 วิ (โหลดโมเดลเข้า VRAM) |
| คำขอถัดไป (โมเดลอุ่นแล้ว) | ~5 วิ |

`serve.py` จึงอุ่นโมเดลไว้เบื้องหลังตั้งแต่ตอนเปิดเซิร์ฟเวอร์ และตั้ง `keep_alive` ไว้
ผู้ใช้คนแรกจะได้ไม่ต้องรอ 53 วินาที

**การรับมือกับโมเดลเล็กที่ไม่ทำตาม schema** — บังคับด้วย `enum` ที่ระดับ schema

## ข้อจำกัดที่ต้องรู้ก่อนนำไปใช้จริง

โปร่งใสไว้ก่อน เพราะสองข้อแรกสำคัญมากถ้าจะเอาไปใช้กับผู้เรียนจริง

1. **เนื้อหาเป็นตัวอย่าง** — ข้อสอบ คลังความรู้ และแหล่งอ้างอิงเขียนขึ้นเพื่อสาธิตระบบ
   **ต้องให้ผู้เชี่ยวชาญแต่ละสาขาตรวจสอบก่อนใช้กับผู้เรียนจริง** โดยเฉพาะเนื้อหา
   ด้านความปลอดภัยและปฐมพยาบาล

2. **การตรวจด้วยกล้องเป็น heuristic ไม่ใช่ pose estimation** — วิธี frame differencing
   วัด *จังหวะ ความนิ่ง ตำแหน่ง และลำดับ* ได้จริง แต่ยังบอกไม่ได้ว่า
   "ข้อศอกงอกี่องศา" หรือ "กดลึกกี่เซนติเมตร" เวอร์ชันใช้งานจริงควรต่อยอดด้วย
   MediaPipe Pose/Hands หรือโมเดลตรวจจับวัตถุ ซึ่งเสียบเข้ากับโครงเดิมได้เลย
   เพราะ `PracticeEngine` แยกส่วน "ดึงสัญญาณ" กับ "ให้คะแนนตาม rubric" ออกจากกันแล้ว

3. **RAG ยังเป็นการค้นแบบคำ (lexical) ไม่ใช่เชิงความหมาย** — คำถามที่ใช้คำต่างจากในเอกสาร
   อาจค้นไม่เจอ และคำที่พ้องรูปข้ามบริบทอาจให้ผลบวกลวง (เช่น ถาม "อากาศวันนี้เป็นไง"
   แล้วไปเจอเนื้อหาเรื่องการระบายอากาศ) เวอร์ชันจริงควรใช้ embedding

4. **บัญชีผู้ใช้ทำงานฝั่งเบราว์เซอร์ล้วน** — มีระบบสมัคร/เข้าสู่ระบบและแยกข้อมูลรายบัญชีจริง
   และรหัสผ่านถูกแฮชด้วย PBKDF2 ไม่ได้เก็บเป็นข้อความเปล่า **แต่ไม่มี backend**
   ใครที่เปิด DevTools บนเครื่องนั้นได้ย่อมแก้ localStorage ได้ ระบบนี้จึงกันได้แค่
   "คนละคนใช้เครื่องเดียวกัน" ไม่ได้กันผู้ไม่หวังดีที่ควบคุมเครื่องอยู่
   ไม่มีการซิงก์ข้ามอุปกรณ์ ไม่มีการกู้รหัสผ่าน และล้างข้อมูลเบราว์เซอร์แล้วทุกอย่างหายหมด

5. **เกียรติบัตรยังอ้างอิงข้ามองค์กรไม่ได้** — เลขที่ใบออกจากเครื่องผู้ใช้เอง จึงไม่มีทะเบียนกลาง
   ให้ตรวจย้อนกลับ การใช้งานจริงต้องย้ายทั้งการตรวจรหัสผ่านและการออกเลขที่ไปฝั่งเซิร์ฟเวอร์
   แล้วทำหน้าเว็บสำหรับตรวจสอบใบ

6. **ห้องครูใช้ข้อมูลจำลอง** — ชั้นเรียนตัวอย่างใน `js/data/community.js`
   ยังไม่ได้เชื่อมกับความคืบหน้าจริงของผู้เรียนหลายคน เพราะยังไม่มี backend
